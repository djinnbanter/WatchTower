### Who is speaking
Me. I run servers. I got sick of bouncing between the host panel, `latest.log`, crash folders, and backup paths when something felt off. I built WatchTower for that. I’m telling you what it does, what it doesn’t, and how to use it — not pitching a lifestyle brand.

- Display lines: 2–5 words when you can. (“Minecraft ops, sorted.”)

- “You still restart it. I just tell you if now is a dumb time.”

- “Whether you’re a beginner or a pro…”

- Explain once in plain English; don’t hide the real product behind slang.

## Product truth (do not drop any of this)

Sources if something conflicts outside this file: `PRODUCT.md`, `README.md`, `docs/ROADMAP.md`, GitHub wiki under `docs/wiki/`.

### What WatchTower is

WatchTower is a jar you drop in `mods/` on a NeoForge dedicated server. It runs on the same machine as Minecraft and opens a web dashboard in the browser (default port **8787**).

It is for server admins — solo operators and small teams — who already run (or sit beside) a host panel like Pterodactyl, Crafty, AMP, or bare metal. Day to day they open it when something feels wrong (lag, crash, failed join, disk pressure, odd shutdown) or for a regular health check.

Data stays on the host under a `watchtower/` folder. No cloud account. No telemetry by default. Free on your machine (GPL-3.0-or-later).

**Works on today:** NeoForge **1.21.x**, Java **21**. Linux dedicated hosts are the common case. Fabric and older NeoForge lines are later, not current marketing promises.

### What WatchTower is not

Say these out loud in copy when people confuse us with neighboring tools:

| We are not… | Use instead / leave alone |
|-------------|---------------------------|
| A host panel (start/stop, files, console) | Pterodactyl, Crafty, AMP, bare metal |
| Player analytics (retention, GeoIP, leaderboards) | Plan and similar |
| Client GPU / graphics crash tooling | Does not apply to headless dedicated servers |
| A cloud-required SaaS | Optional Cloud is a later paid bet; local stays free |

WatchTower **does** show who is online during lag or crashes. That is ops triage, not player surveillance. Do not market it as analytics.

### The two questions (section beat — not the hero)

1. **Is the server okay right now?** — health grade, live vitals, restart advice (advisory only).
2. **What should I fix next?** — Issues, crashes, mods, backups, world pressure, join problems. Each row says what to do.

Everything else on the site should support those two questions.

### How it works (non-technical)

Three layers. Day-to-day use only needs the first two.

#### Watching
Live charts and vitals while Minecraft is running. TPS, lag, memory, players, CPU, disk — updating whether or not someone has the dashboard open.

#### Scanning
About once a minute: logs, crashes, mods, activity, and the Fix inbox. Keeps Issues and related tabs current without asking the admin to run a giant “deep audit” every visit.

#### Support compose (on request)
When you need to share evidence with a helper or mod author, you build a redacted zip (Support pack). That is a snapshot for sharing — not the normal way the dashboard stays fresh.

**First-run:** after install, a wizard walks through account setup, options, an initial discovery pass, backups, and security. After that, Watching + Scanning keep the desk useful.

**Optional companions:**
- **Spark** (separate mod) for lag proof — WatchTower reads Spark profiles and turns them into plain steps.
- **Modrinth** lookups (optional, privacy toggle) for mod identity and update hints. WatchTower does **not** download mod jars for you as a silent pack change. Assisted jar changes (when shipped / gated) require an explicit confirmed job from an account allowed to mutate mods — never quiet downloads, never auto-restart.

### Promises that do not change

Keep these honest in every rewrite:

1. **Your data stays yours** — files on the server; no log upload by default. Anonymous diagnostics and any future Cloud sync are explicit opt-in.
2. **You’re in control** — network features are opt-in; risky actions show preview / undo where they exist; nothing quietly edits mods or the world.
3. **Ops, not surveillance** — help run the server; do not track players like an analytics product.
4. **Drop-in beside your host** — a jar in `mods/`, not a second control panel you have to keep running.

#### Advisory only (critical for copy)

WatchTower **does not**:
- Restart the server or schedule restarts for you
- Kill entities or unload chunks
- Silently edit mods or worlds
- Replace the host panel

It **recommends** restarts, RAM changes, jar checks, quiet windows, and next steps. The admin (or their panel) still does the action.

### Install story (what the user actually does)

1. Download the NeoForge jar (required) and optionally the CLI jar (disaster recovery when the game will not boot) from Modrinth or GitHub Releases.
2. Put them in the server’s `mods/` folder.
3. Restart the server.
4. Open `http://<server-ip>:8787` (prefer localhost or SSH tunnel — do **not** expose 8787 to the open internet).
5. Sign in with default `watchtower` / `password`, **change the password immediately**, finish first-time setup.

Primary CTAs that already match product truth: **Try the demo** (same UI, sample data) and **Get it on Modrinth**.

## Feature map — full product surface

Grouped the way the dashboard rail is grouped. Each block: what it is, what it does for the admin, what to say / not say. On Features, try to cover every major surface; if you compress or reorder for a stronger story, note what you dropped and why.

### Monitor

#### Overview
**What it is:** First screen after login — mission control.  
**What it does:** Shows a health grade (Strong through Poor), a short “needs attention” list, live vitals teasers, and **restart advice** (Safe / Caution / Wait). Jump cards into performance, weekly digest, storage, Spark, boot profile.  
**Marketing note:** Restart advice is advisory only. Never imply WatchTower restarts anything.

#### Live
**What it is:** Right-now ops console.  
**What it does:** Charts for TPS, MSPT (tick time), players, memory/heap, CPU, disk, and (when reported) network, thermals, background world work. Time windows from a few minutes out to longer history.  
**Marketing note:** “You do not need `latest.log` open for the basics.” Calm correctness over flashy animation.

#### Insights
**What it is:** Patterns over days/weeks — not the live second.  
**What it does (sub-views):**
- **Schedule** — busy vs quiet hours; suggested restart / maintenance window (suggestion only).
- **Load** — load patterns over the window.
- **Incidents** — recurring incident shape.
- **Configs** — read-only keep / tweak / why for server config and JVM-ish health; RAM sizing advice that compares host memory to Java heap settings (conservative — may say lower `-Xmx` or raise the plan, not “just add RAM”).
- **Mod changes** — pack churn over the window.
- **World** — entity/chunk pressure vs busy-hour baselines and peak minutes (7d / 30d).
- **Storage** — disk runway (roughly how many days left), dimension breakdown, space map / treemap.
- **Digest** — weekly ops rollup from data already on the host: grade, crashes, disk, MSPT trend, mod changes, one next action. Local only — no outbound mail/webhooks required.

**Marketing note:** Live = this second. Insights = the repeating pattern / planning tools.

#### Session
**What it is:** Who is on the server and recent join/leave activity.  
**What it does:** Online roster, peaks, player directory, playtime depth, **Session activity** feed (joins, leaves, pack-sync rejects).  
**Related:** **Join clinic** (below) lives here for failed pack-sync joins.  
**Marketing note:** Not a ban tool. Not analytics. Ops context for restarts and join failures.

#### Startup
**What it is:** Last boot verdict.  
**What it does:** Boot phases with timing, warnings/errors, boot history, launch/config notes. Links into Issues when boot findings become fix cards.  
**Marketing note:** Useful after restarts or crash loops that still reach a running process. If the game never stays up, point to disaster recovery CLI instead.

### Triage

#### Issues (Fix inbox)
**What it is:** The ranked list of “fix this next.”  
**What it does:** Active vs Reviewed queues. Severity bands (Critical / Warning / Info). Each card has a **Fix** tab (next step) and **Details** (evidence), with links into Crashes, Mods, Live, Sources, etc. Marking reviewed clears the inbox; files stay on disk.

**Kinds of findings that land here (examples):**
- Lag / performance and soft hang (“server process up but ticks frozen”)
- Crash pointers
- Jar drift (same filename/version, different checksum — pack may have been quietly swapped)
- Likely client-only jars sitting on a dedicated server
- Silent script / datapack failures (KubeJS, CraftTweaker, datapack `/reload` errors that never crash the server)
- World pressure (item storms, mob spikes, chunk / pregen disk pressure)
- Join clinic pack-sync rejects
- Backup not set up / stale backups (when tracking is enabled)

**Marketing note:** Continuous Scanning fills this inbox. Do not sell “run a giant weekly report” as the daily path.

#### Crashes
**What it is:** Crash report review with grouping.  
**What it does:** Matching crash shapes stack into fingerprint groups so you are not re-reading the same dump. Each group: Fix steps, Evidence (stacks/files), Details (fingerprint metadata). Mark reviewed without deleting files.  
**Also:** Odd shutdowns when `latest.log` stops with **no** crash report — e.g. OS OOM-killer vs panel force-kill (**Killed** / external kill path) with the right fix story.  
**Marketing note:** “Names the likely mod and the fix in plain English” is fair when evidence supports it; do not claim magic certainty.

#### Spark
**What it is:** Lag proof reader (needs [Spark](https://modrinth.com/mod/spark) installed).  
**What it does:** Import a saved `.sparkprofile` (or a spark.lucko.me URL once) and turn it into Overview / Findings / World / Map / Sources / Timeline / call paths. Optional auto-capture on critical lag.  
**Marketing note:** Deep Spark workspace depth is still **alpha**. Day-to-day lag triage starts on Live + Issues; Spark is for proof when you need it.

#### Logs
**What it is:** Browse server log files from the dashboard.  
**What it does:** Filters and file browsing when Fix / Evidence points at raw logs.  
**Marketing note:** Utility surface — not a hero feature.

### Ops

#### Mods
**What it is:** Pack inventory and mod forensics suite.  
**What it does:**
- **Library** — full catalog with All / Enabled / Disabled / Client / Server filters; project pages per mod
- **Updates** — newer versions WatchTower knows about, with Safe / Caution / Break / Unknown pack-impact labels
- **Conflicts** — version / dependency clashes
- **Log errors** — mod-related errors from Scanning
- **Changes** — recent add/remove/update; jar drift when contents change without a version bump
- **Modrinth** — optional online metadata (no world/player upload)
- **Forensics** — deep jar / package ownership when debugging
- **Disable / Enable** (admin/owner) — soft-rename jar to `.disabled` / back (no Delete from dashboard); world-risk badges when disabling may break the save
- **Config editor** (admin/owner) — edit that mod’s `config/` files with preview, timestamped backups, undo (not `server.properties` / world serverconfig / jars)

**Marketing note:** Modrinth is lookup/hints. Never say WatchTower silently downloads or updates the pack. Assisted mutate paths are confirm-gated and do not auto-restart.

#### Backups
**What it is:** Backup freshness tracking — not a backup engine.  
**What it does:** Point WatchTower at a **local backup folder** (best path) and/or experimental panel/cloud heartbeat signals. Shows whether backups look fresh; Issues/Overview can warn when stale or unset.  
**Marketing note:** Panel/cloud tracking is **alpha** — prefer local folder in honest copy. WatchTower does not invent where backups live; the admin chooses.

#### Activity
**What it is:** Timeline of what happened on the box.  
**What it does:** Commands, joins, lag events, jobs — stitches incident stories (e.g. lag → crash → missed backup) for context.  
**Marketing note:** Useful for “what happened last night?” storytelling on the site; keep claims grounded.

#### Sources
**What it is:** Health of Watching / Scanning / Support jobs.  
**What it does:** Shows when each poller last updated and when the next pull is due — answers “is WatchTower actually working?”  
**Marketing note:** Meta-ops. Good for FAQ (“why does my Issues list look empty?”) not homepage hero.

### System and sharing

#### Help Center
In-app wiki (same content as the public GitHub wiki): guides, search, Support pack shortcut.

#### Settings
General (appearance, timezone), Monitoring, Backups, Alerts, Security, Accounts, Audit log, Integrations, About. Theme/accent can sync per signed-in account.

#### Accounts and audit log
Named logins for shared desks: **owner** / **admin** / **viewer**. Owner manages accounts; audit log records who changed what. Optional Minecraft player link for rail skin. Optional **2FA**.

#### Support pack
Build a redacted zip (presets, logs, crashes, Spark references, extras) from the side rail / Overview / Help Center to send to a helper or mod author. Secrets scrubbing is part of the product. Copy-friendly bits for Discord where available.  
**Marketing note:** Sharing is deliberate and local; nothing auto-uploads.

#### Security posture
Login required. Change default password. Prefer SSH tunnel / localhost for 8787. Do not market “expose the dashboard to the internet” as normal.

#### Disaster recovery (CLI)
When Minecraft will not stay up, the dashboard is gone. Matching **CLI jar** (kept in `mods/` but run with `java -jar` over SSH) builds a local disaster-recovery bundle. Browser DR viewer analyzes in-browser — nothing sent to WatchTower servers. Full Fix-tab reliability in the viewer may still be catching up; opening the zip and reading logs is always valid.  
**Marketing note:** Recommend shipping the CLI jar next to the mod “before you need it.”

#### Roadmap (in-app)
Honest “works today / coming next / not our job” — same spirit as `docs/ROADMAP.md`. Do not invent ship dates.

## Plain-English product summary (facts only — rewrite in the voice above; do not use as the hero)

WatchTower is a NeoForge server mod with a local web dashboard. It watches your dedicated Minecraft host while the game runs, keeps a ranked Fix list of what to deal with next, and helps you read crashes, lag, mods, backups, disk, and join failures without bouncing between the panel, logs, and crash folders. It does not replace your host panel, does not track players like an analytics product, does not require a cloud account, and does not restart or quietly change your server for you. You install a jar, open the dashboard on the machine (or through SSH), and get straight answers: is the server okay, and what should I fix next.
