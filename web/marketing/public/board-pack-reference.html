[ MOD ]

WatchTower Mod

Free forever. Brain mostly inside the game. Sits beside whoever already starts/stops the server.

Commercial · Free
Control · None

01 · Sensors

In-game

  • Tick / live metrics (TPS, MSPT, CPU, memory)
  • Soft hang / freeze signals
  • Players · joins · session
  • Crash files · peeks (lag, disk, backups…)

02 · Signals

On the host disk

  • Ops notebook under watchtower/
  • Issues · activity · peeks written locally
  • Nothing leaves the machine by default

03 · Brain

Inside the JVM

  • “Is the server okay?” grade
  • Issues open/suppressed
  • Crash review · mod update impact
  • Competes with the tick — keep it honest

04 · Desk

Local dashboard

  • Browser → embedded HTTP on the machine
  • Default port example: 8787
  • Prefer localhost / SSH tunnel

05 · Actions

Advisory only

  • Fix guidance · Support packs
  • Assisted mod confirm (no silent mutate)
  • No start / stop / kill

Dead path

When Minecraft is dead, Mod sensors and brain stop with the process. Lifecycle stays with the owner’s host panel (Crafty / Ptero / AMP / bare metal). Files on disk may still be there for the next boot — the jar cannot phone home while the game is down.

[ CLOUD ]

WatchTower Cloud

Paid opt-in. Same jar as sensor. Brain moves off-box so it is not stuck only in the server thread.

Commercial · Paid
Control · None

01 · Sensors

Same Mod sensors

  • Jar-drop onboarding unchanged
  • In-game Watching + Scanning while up
  • No second install required to start Cloud

02 · Signals

Local + ship up

  • Ops notebook still on host
  • Opt-in events / snapshots → Cloud
  • Explicit pairing / enable — not silent telemetry

03 · Brain

Off-box

  • Fleet view across servers
  • History when a node goes dark
  • Heavier analysis · alerts
  • Survives tick pressure on the game

04 · Desk

Cloud ops desk

  • Remote multi-server account surface
  • Local desk can still work on LAN
  • Same “okay?” language as Mod

05 · Actions

Notify · history

  • Alerts that reach the operator
  • Retention / review after the fact
  • Still no start / stop on the host

Dead path

Cloud keeps last-seen + history from signals already shipped — better than Mod alone when the box is dark. Stronger “process died while Minecraft was down” can come later via an optional host watch — never part of free Mod onboarding, never required to begin Cloud.

Cloud → Panel gate

Panel funding unlocks when Cloud shows multi-server operators returning for fleet/history — not when engineering wants a new project. Board approves Panel in principle only; build starts after this gate.

[ PANEL ] · conditional

WatchTower Panel

Full suite. Looks in from outside. Replaces Crafty / Lodestone-class tools for this audience. New servers get the companion jar by default.

Commercial · Suite
Control · Full

01 · Sensors

Outside-in (+ jar)

  • Process · console · files · crash folders · exit codes
  • Default: companion jar auto-dropped into mods/ on create
  • Opt-out allowed for naked instances
  • Jar must match loader / MC version

02 · Signals

Panel store + notebook

  • Panel-owned instance state
  • When jar is up: same rich ops notebook as Mod
  • Optional later attach to Cloud

03 · Brain

On the panel host

  • Same ops language as Mod / Cloud
  • Works while game is down (outside-in)
  • Deeper live Watching when companion jar is loaded

04 · Desk

One suite UI

  • Control plane + ops desk together
  • Create server → jar present by default
  • Companion status: installed / missing / outdated

05 · Actions

Hands + brain

  • Start / stop / kill / files / console
  • Plus Fix guidance · Support packs
  • New trust bar: observe vs operate must stay clear

Dead path

When Minecraft is dead, Panel still operates the machine (files, console, restart). Companion jar is idle until the server boots. You do not need a separate host panel — WatchTower Panel replaces Crafty / Lodestone-class tools for this audience.

Audience · Mod ± Cloud

Keep Crafty / Ptero / AMP. WatchTower sits beside them. Never forced onto Panel.

Audience · WatchTower Panel

One suite: run the process and triage the pack. Replaces Crafty-class — not “Crafty plus a plugin.”

WatchTower board pack — three products

ASK
Approve the three-product strategy and a phased build mandate: deepen Mod (Phase 1), build Cloud (Phase 2), and approve Panel (Phase 3) in principle only after Cloud proves fleet value and retention. No budgets. No ship dates.

LADDER
1. Mod (free) — Drop jar in mods/, local desk. Brain inside the game JVM. Advisory only. Sits beside Crafty/Ptero/AMP. When Minecraft is dead, the mod cannot talk.
2. Cloud (paid) — Same jar ships signals up. Brain off-box: fleet, history, heavier analysis, alerts. Still no start/stop. When dark: last-seen + history; optional host watch later, never required for free onboarding.
3. Panel (suite, gated) — Outside-in control plane + ops brain. Replaces Crafty/Lodestone-class for Panel customers. Default: auto-install companion jar on new servers (opt-out OK). When Minecraft is dead, Panel still operates the machine; jar idle until boot.

SHARED
One “is the server okay?”, Issues/crashes/Fix hints, mods story, Support privacy — learning transfers across products.

GATE
Panel funding unlocks when Cloud shows multi-server operators returning for fleet/history — not when engineering wants a new project.

WON’T
No Cloud-required free tier. No forced Panel on hosted users. Jar-drop stays sacred.
